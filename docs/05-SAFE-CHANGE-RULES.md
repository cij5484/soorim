> **예약 앱은 실제 매장에서 운영 중이다.** 실제 코드가 문서와 다를 경우 최신 코드가 우선이며 문서를 함께 갱신해야 한다.

## 1. 기본 원칙

1. 원격 최신 `main`과 현재 파일을 먼저 확인한다.
2. `rg -n "검색어" index.html`처럼 실제 이름을 찾고, 존재하지 않는 함수·변수·선택자를 새 기준인 것처럼 만들지 않는다.
3. 요청 범위 밖 파일·화면·동작을 수정하지 않는다.
4. 정상 기능을 삭제하거나 “간단하게” 다시 만들지 않는다.
5. 요청 없는 큰 리팩터링, 파일 분리, 폴더/데이터 구조 변경을 하지 않는다.
6. `dist/`, 번들 또는 임의 결과물을 만들거나 커밋하지 않는다.
7. 비밀번호, 개인 인증정보와 Firebase 비밀정보를 문서·로그·커밋에 남기지 않는다.

## 2. 매우 민감한 기능

다음은 작은 변경도 매장 운영과 데이터에 영향을 줄 수 있으므로 요청이 없으면 수정하지 않는다.

- 예약 추가·수정·삭제
- 붙여넣기 불러오기와 파싱
- 중복 예약 및 기존 예약 수정 판정
- 취소 의심 목록과 삭제 흐름
- 시간·룸·테이블 충돌 체크
- 테이블 이동과 홀·룸 좌석맵
- Firestore 컬렉션·문서·필드 및 저장 방식
- PC/모바일 TV 실시간 동기화와 리스너 수명주기
- 예약/도착 등 상태 변경
- PWA manifest, 서비스워커와 캐시

수정 요청이 있더라도 관련 함수의 호출자, Firestore 쓰기 범위, PC/모바일 분기와 기존 데이터 fallback을 먼저 확인한다.

## 3. 버튼·클릭 문제 확인 순서

1. 생성된 HTML의 inline `onclick` 따옴표/이스케이프가 손상됐는지 확인한다.
2. 모듈 안 함수가 inline HTML에서 필요하면 `window`에 실제 등록됐는지 확인한다.
3. 자식 버튼의 `stopPropagation()` 필요성과 기존 사용을 확인한다.
4. 이벤트가 bubble(자식→부모)인지 capture(부모→자식)인지, 두 단계에 중복 핸들러가 없는지 본다.
5. `preventDefault()`가 링크·폼의 기본 동작을 막는지 확인한다.
6. `renderTVView()`처럼 PC와 모바일이 별도 HTML을 만드는지 둘 다 검색한다.
7. 이벤트 위임은 `tvRowStatusClickHandlerBound` 같은 중복 등록 방어가 있는지 확인한다.

한 증상만 고친 뒤에도 행, 내부 버튼, 배경, PC와 모바일을 각각 클릭 테스트한다.

## 4. 코드 수정 지시 방법

- “버튼 근처” 대신 실제 검색어·파일·함수명을 쓴다. 예: ``index.html`의 `handleTVRowStatusClick()` 안 조건`.
- 같은 문자열이 여러 곳이면 함수명과 앞뒤 고유 코드를 함께 지정한다.
- 넓은 블록 교체가 꼭 필요하면 시작점과 끝점을 고유한 코드로 명시하고 교체 전후 diff를 검토한다.
- 정상인 호출자와 다른 화면 분기는 건드리지 않는다고 작업 범위에 명시한다.
